# 2026-10-16 · v0.8.1 详情页骨架屏（修「正文挤掉作者行」的跳位）

驾驶员反馈：「点开详情时，正文会先渲染出来，其他的都偏慢……每次正文都会短暂的挤掉
发布者的信息和浏览量、关注私信之类的按钮」——要求解决，建议加占位加载的骨架屏。

## 原因（大白话）

详情页数据分两步来：

1. **REST 接口**：拿标题 + 正文——快；
2. **整页 HTML 抓取 + 解析**：拿作者行（关注/私信按钮）、浏览量、面包屑、付费区等——慢。

界面原先按「谁先到谁先画」：正文先出现在页面顶部，第二步数据到了以后，
作者行/计数行被**插到正文上方** → 正文被整体往下挤，观感是「闪一下跳下去」。

## 做法（驾驶员建议的骨架屏，就地替换不跳位）

- **首帧即整页骨架**（替换原来的居中转圈）：标题条 + 头部骨架 + 正文条 + 图片块，
  可滚动；REST 返回前就占好版面。
- **头部骨架占位**：正文已显示、整页解析未返回时，作者行（头像圆 + 名字/日期条 +
  右侧「关注/私信」两枚按钮位）、计数行、面包屑位都用**呼吸脉动**的灰条占住，
  高度对照真实头部（44dp 头像、32dp×2 按钮列 ≈ 行高 68dp、面包屑 chip 22dp）。
  解析返回后就地替换成真实内容 → 正文不再被挤动。
- **解析失败兜底**：`detailFailed` 标志（VM 新增）——整页解析失败时骨架让位，
  正文照常显示（原因仍走 Toast 提示），避免骨架卡死在屏幕上。

## 实现

- 新 `app ui/detail/DetailSkeleton.kt`：`DetailSkeletonPage`（整页）/ `DetailHeaderSkeleton`
  （仅头部）；占位色 = `onSurface` 低透明度 + 850ms 呼吸动画（浅深色主题通用）
- `DetailViewModel`：`UiState.detailFailed`（load 时复位、解析成功清除、失败置位）
- `DetailScreen`：`loading` 分支 → `DetailSkeletonPage`；头部区 `detail == null && !detailFailed`
  → `DetailHeaderSkeleton` 占位项
- 版本 0.8.1(9)
