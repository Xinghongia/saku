# 2026-10-15 · 登录滑块验证（v0.3）

驾驶员反馈：真机登录显示"登录失败"。二次勘察站点登录链路，确认 zibll 滑块验证是**强制**的，
按"复刻官方流程、不绕过"实现原生滑块并通过真机登录。细节决策见 `总设计案.md`。

## 二次勘察：滑块是强制的

首轮勘察（同日早前）时匿名提交 user_signin 曾"看起来能过"，这次带真实账号复测才暴露真相：

| 场景（curl 实测） | 站点响应 |
|---|---|
| 不带滑块数据提交 | `{"error":1,"msg":"环境异常，请刷新后重新提交"}` |
| 带滑块数据但距缺口偏 50px | `{"error":1,"msg":"环境异常，人机验证失败"}` |
| 带滑块数据、距缺口偏 6px（网页容差 8px 内） | `{"error":0,"reload":1,"msg":"成功登录，页面跳转中"}`，下发 `wordpress_logged_in_*` cookie |
| 距缺口正确但轨迹全 0（对照实验） | 通过 —— 服务端只校验对齐，不校验轨迹方差（如实记录，客户端不利用此点：轨迹照录真实拖动） |

结论：**服务端校验的是"拖动位置与出题缺口是否对齐"**。早期"未强制"的判断是错的
（匿名 test 未触发该校验），已修正。

## 滑块流程解剖（zibll v9.1 前端源码，2026-10-15 实测）

链路：登录页 → `loader.js`（模块加载器）→ `main.min.js`（表单提交 zib_getX）→
`captcha.min.js` → `slidercaptcha.min.js`（拼图组件）。完整流程：

1. **出题**：随机缺口 `x ∈ [73,217]`、`y ∈ [28,97]`、背景图 `captcha/N.jpg`（N=0~20）；
   按特定编码生成 `randstr`（结构 `<11..40><n 个小写字母><x><m 个小写字母><11..40>`，内嵌答案 x）
   请求 `themes/zibll/action/captcha.php?type=slider&randstr=…`，换回 `token / rand_str / check`；
2. **拖动**：滑条位移 a∈[0,240] 映射拼图块视觉位置 `d = 220/240·a`（网页系数），拖动中记录纵向轨迹；
3. **提交**：`ticket`（同款编码，内嵌拖动距离 d）、`randstr`（= `o + rand_str[o:r] + r`，
   o∈[1,9]、r∈[15,25] 随机）、`spliced`（|d−x| < 8）、`trail`、`check`，
   以 `captcha[ticket]` 等 jQuery 嵌套字段并入登录表单。

## 实现（P6 登录链路）

**core**（新增 `SliderCaptcha.kt` + 改 `AuthApi.kt`）：

- 出题、编码（randstr/ticket/randstr 字段）、坐标数学（`dragToDistance`、`isAligned`）、
  `solve(challenge, drag)`、`requestChallenge()` 全部按网页算法 1:1 复刻
- `AuthApi.signIn(username, password, captcha: Solution?)`：带滑块数据时提交 `captcha[*]` 字段族；
  「环境异常」两类响应映射为 `NeedsCaptcha`
- 设计原则：**数据全部来自用户真实拖动**（x 随机出题、d 由实际拖距算出），客户端不伪造对齐、
  不试探容差边界
- 单测 62 → **76 项全绿**（新增 14 项：编码结构模拟服务端解码回验、坐标数学、mock 联网换凭据）

**app**（新增 `SliderCaptchaDialog.kt` + 改 `LoginViewModel` / `LoginScreen`）：

- Compose 拼图弹窗：背景图 + 缺口 + 可拖动拼图块（`puzzlePath` 复刻网页 canvas 路径形状）、
  下方滑动条整条可拖（移动端手指友好）、拖动记录轨迹、对齐自动提交、未对齐换图重试
- 登录流程：点「登录」→ 先查 `captcha_mode` → `slider` 则弹拼图 → 拖对后带数据提交
- 登录成功 0.9s 后自动返回上一页；`NeedsCaptcha` 时重新弹出拼图

## 真机联调（vivo V2073A / Android 13）

- 驾驶员真机输入账号密码，**登录成功**：「登录成功，页面跳转中」（站点原话），
  「我的」页显示已登录（截图 `15-login-success.png`、`16-profile-logged-in.png`）
- 修复 1：旧版登录成功后停在登录页（"页面跳转中"是网页端行为，App 未接）→ 加自动返回
- 修复 2：已登录时「我的」页仍显示"登录 / 切换账号"入口 → 改为按登录态显示（未登录才出现）
- **驾驶员自测通过（driver 门）**：退出登录 → 重新登录成功 → 自动返回。
  站点强制滑块，此次重新登录走通了完整滑块弹窗流程（拖动 → 对齐 → 提交 → 成功）

## 踩坑

1. **core 的 okhttp 必须声明为 `api(...)`**：否则 app 端按 coil 传递的 okhttp 4.x 编译，
   `response.body` 类型不一致（`ResponseBody?`）直接编译失败；运行版本仍是 5.x，属于编译期陷阱
2. adb 自动化输入受本机百度输入法干扰（`@`、数字被联想替换），UI 自动化测试账号输入不可靠；
   真机验收以驾驶员手动输入为准
