# 2026-10-16 · v0.7 付费图片资源（二维码）显示与离线解析

驾驶员实测买了站点新类型的资源（36023）后发现：**新资源改成付费后给图片（云盘二维码截图），
不再给网盘链接**，老资源才有 `/pay-download` 按钮；App 里买完这类资源什么都不显示。
要求：① 显示图片；② App 内解析二维码；③ 方便复制链接。

**已确认的边界（沿用红线）**：图片只来自站点渲染给已购用户的 HTML（与网页可见性一致，
不绕过门禁）；客户端只拉取本来就要显示的图片本身，不发额外探测请求；解出的链接
= 用户自己扫码的等价结果，不伪造、不代下单。

## 站点机制（2026-10-16 实测 36023 已购 / 36018 未购）

| 形态 | 标记 |
|---|---|
| 类型判定 | `#posts-pay` **盒内**有 `i.fa-file-image-o`（付费图片）或 `.imgbox-container`；旧下载型是 `i.fa-download`。**不能用 `.pay-tag` 判定**（已购图片型的盒子里没有它，侧栏才有同类元素） |
| 已购·图片型 | `.paid-gallery .imgbox-container .swiper-slide img`：`data-full-url` = 原图 PNG（~200px），角标 badge 文本 "1/2"；订单信息结构同旧型 |
| 未购·图片型 | `.pay-thumb img` = 站点给的模糊封面（data-src）+ `.pay-thumb .abs-center` =「共2张图片 请付费后查看」；价格/cashier-link 同旧型 |
| 二维码图 | 公开可下载（无需 cookie，HTTP 200，~16KB/张）；图片底部有说明文字条「截图保存二维码，扫码获得文件」 |

**解码可行性先验证**：两张真样本（`research/probe/img1.png`、`img2.png`）本地解码均得到
`https://pan.quark.cn/s/...?entry=webother`。

## 实现（core **157 项测试全绿**；app 编译通过，0.7.0(7) 已装机）

**core**
- `QrDecoder.kt`（新，纯 JVM，依赖 zxing 3.5.4）：`decodeArgb(pixels, w, h)` 多趟——
  ① HybridBinarizer 原图 → ② GlobalHistogram 原图 → ③ 小图（短边<400）最近邻放大 3 倍 →
  ④ 裁掉底部 18%（说明条）后放大 2 倍；hints：QR_CODE / TRY_HARDER / UTF-8 / ALSO_INVERTED；
  全失败返回 null。含 `scale` / `cropTop` 内部工具（放大有 8M 像素内存守卫）
- `PostDetail.kt`：`PayKind{Download,Images}`、`PayImage(url,label)`；
  `PayBox.Unpaid`+kind/teaserImageUrl/hintText；`PayBox.Paid`+kind/images（新字段带默认值，旧样本不受影响）
- fixtures（走 FixtureBuilderScratch）：`post_pay_images_sample`（36023 已购）/`post_pay_images_unpaid_sample`（36018 未购）；
  builder 补资源标题与二维码原图文件名的脱敏映射；`.gitignore` 的 Scratch 条目改为通配 `*Scratch.kt`
- 测试 +10：`QrDecoderTest` 7 项（编解码回环/底部说明条/小图放大/反色/噪声 null/非法尺寸/工具函数）、
  `QrProbeScratch`（真样本解码，本机运行，clones 跳过）、`PostDetailParserTest` 图片型两态 + 旧两型补 kind 断言

**app**
- `PayImageQr.kt`（新）：GET 图片（体积上限 8MB、循环读）→ BitmapFactory 两段式
  （尺寸守卫边≤8192/≤32MP，长边缩到 ≤2048）→ ARGB 像素 → `QrDecoder`（Default 线程）
- `DetailViewModel`：`QrState{decoding,link,failed}` + `UiState.qr: Map<url, QrState>`；
  已购图片型加载后自动识别前 8 张（Semaphore(2) 限并发）；**已有终态不重复解**（购买后重载/登录态刷新同一守卫）；
  `retryQr` 手动重试；`showQrLink` 复用通用「链接」对话框（复制/浏览器打开）
- `PayCard`：已购图片型 = LazyRow 缩略图（点开全屏）+ 每张下方状态
  （识别中转圈 / 「网盘链接」点开对话框 + 复制按钮 / 「未识别到二维码 · 点击重试」）；
  未购图片型 = 顶部预览（blur 仅 API 31+，统一叠遮罩 + 「请付费后查看」文案），标签改「付费图片」
- `DetailScreen`：全屏查看器（黑底 Fit、点空白关闭、底部显示标签与已解出链接 + 复制/浏览器打开）；
  通用链接对话框标题「下载链接」改「链接」（现在也服务二维码）

## 走查期修复（驾驶员 2026-10-16 首轮反馈，已改并重装机）

1. **二维码第二张要横滑才看全** → 缩略图宽度改为按卡片可用宽度自适应
   （`BoxWithConstraints`，`(可用宽 - 间距) / 2`），同屏两张完整显示，不用滑
2. **没封面的文章 / 没设头像的用户不显示** → 全面补默认占位：
   - 头像：`UserAvatar` 把人形图标垫在图片下层（地址为空、加载中、加载失败都会露出），
     全 App 头像位（评论/卡片/私信/资料页等）一次性受益
   - 封面：新增 `CoverPlaceholder`（图片图标 + 淡色底）——列表卡片、详情页「TA 的文章」、
     付费图片缩略图、作者页封面条、编辑资料封面、我的页封面（主题色垫底）
   - core `SiteParser.imageUrl`：gravatar/geekzu 头像**保留 `d=` 查询参数**
     （站点把默认头像地址放在这个参数里；此前剥掉 query 后请求会落到 gravatar 自己的
     蓝色默认图，且国内网络下 gravatar.com 常不可达）→ 配单测
3. 反思：占位图不要"什么都不画"等加载成功——加载失败在弱网下很常见，
   默认底图必须由客户端自己兜（本地绘制，不依赖站点素材，也不引入第三方主题资源）

## 设计要点与坑

- 类型判定必须在 `#posts-pay` 盒内找图标：页面别处有同名 `pay-tag`/`已售` 元素，全局找会误判
- 已购图片型盒内**没有** `.pay-tag`（只有未购/侧栏有）——最初想用它判定 kind，实测否定
- 图片底部说明文字条会干扰定位图案附近的二值化 → 保留「裁底 18% 再试」兜底趟
- Blur 效果 API 31+ 才有 → 旧机型靠深色遮罩 + 文案保证「未解锁」观感（与网页观感一致优先，不追求像素级）
- 解码失败不清空/不藏图：全屏查看器仍可看图（用户还能自己截图扫），识别只是便利
- zxing 只在 core 内用，app 不直接依赖（APK 约 +0.6MB）
