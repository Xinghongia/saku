# 2026-10-16 · Release 打包（开源准备第二批）

驾驶员触发 Parking Lot 的「Release 打包」。目标 = 出可直接分发安装的正式签名 APK。
本批**只动构建配置，不改任何应用代码**；产物行为与 v0.9.2 走查通过的调试版一致（minify 未开）。

## 做了什么

- **发布签名密钥（本机生成，不入库）**：`keytool -genkeypair` → 仓库根 `saku-release.jks`
  （RSA 4096 / 有效期 10000 天 / alias `saku`）；口令随机生成，只写进同目录
  `keystore.properties`（两者一并被 `.gitignore` 挡下，`git check-ignore` 已复核）。
  **这两个文件是 App 的「身份证」：给已安装用户升级必须沿用同一把钥匙，丢失则无法覆盖安装
  ——由驾驶员负责备份（建议两件一起备份）。**
- **`app/build.gradle.kts` 条件签名**：从 `keystore.properties` 读四项凭据（文件存在才配
  release 签名；缺失时仍可构建出未签名包，保证他人 clone 仓库也能跑通 `assembleRelease`）
- **`.gitignore`** 新增：`keystore.properties`、`*.jks`、`dist/`（出包目录）
- **出包**：`dist/SakuraXy-v0.9.2.apk`（由 `app/build/outputs/apk/release/app-release.apk` 复制）

## 注意与遗留

- **签名不同互斥**：release 签名 ≠ 调试签名——手机上装过调试包的需先卸载才能装 release
  （会清掉本地登录态与设置）；调试包与 release 包不构成升级关系
- **R8/minify 未开**：保持与走查版本一致的行为；要瘦身（预测可减 30%+）再单独一批做，
  并需真机回归（Jsoup/kotlinx.serialization/Coil 的反射面要单独验证）
- 未创建 GitHub Release（把 APK 挂为附件是发布动作，由驾驶员触发）
- README 构建章节暂未提签名（他人 clone 不持密钥，`assembleRelease` 得未签名包属预期，
  无需文档处理）
