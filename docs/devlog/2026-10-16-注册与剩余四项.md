## 站点机制（2026-10-16 实测自 `signin.html` 保存页 + 标签页 200 抓取）

| 流程 | 字段 / 机制 |
|---|---|
| 注册（#tab-sign-up） | `name` + `email` + `captch`（邮箱验证码）+ `password2` + `user_agreement` 复选 + `captcha_mode=slider` + `_wpnonce` → `action=user_signup`；发码按钮 `form-action=signup_captcha`（http 响应含 `remaining_time` 重发间隔） |
| 找回密码（#tab-resetpassword） | `email` + `captch` + `password2` + `repassword` + `repeat=1` + 滑块 + nonce → `action=reset_password`；发码 `resetpassword_captcha` |
| 滑块要求 | 与账户安全一致（v0.5 实测结论）：**每次提交含发验证码都要带真实拖动数据** |
| 标签归档页 /tag/xx | 与分类页**同构**：`.page-cover-con .title-h-left b`（名称+篇数）、`posts.posts-item` 卡片、`.pagenav`（含 `input.jump-input max=18`）、`?orderby=` 排序菜单均可；**卡片上只列分类不列标签**（与网页一致） |
| 使用手册 /manual | WordPress **page**（id 29834），REST `pages?slug=manual&_fields=id,title,content` 直接可取全文（11KB 正文：目录/注册/登录找回/用户中心/积分余额…） |
| 登录页还有 | GitHub OAuth 社交登录按钮（`/oauth/github?rurl=…`）——本期不做（见调研结论） |

## 走查修复（2026-10-16，驾驶员实测「成功啦！」后发现的衔接问题）

驾驶员反馈：注册成功（站点开启「注册后自动登录」，应答已带登录 cookie），但 App 仍停在
登录页并提示「请使用新密码登录」；再点登录时站点回「已登录」——状态与界面不一致。

原因：注册应答里的登录 cookie 已进会话（Session 会自动 bump revision，其他页面其实已
按登录态刷新），但注册流程**没检测也没落盘**这个登录态，界面照旧回了登录页。

修复（如实反映真实状态，与网页「注册后刷新即是登录态」一致）：
- 注册/找回密码成功时检测 `session.isLoggedIn()`：
  - 已登录 → `sessionStore.save(snapshot())` 落盘 + 提示「注册成功，已自动登录」；
    导航 `popBackStack(LOGIN, inclusive)` **连同登录页一起退出**，回到来处（已是登录态）
  - 未登录（站点若关闭自动登录）→ 维持「请使用新密码登录」+ 回登录页
- 找回密码同一处理（同机制：应答若带登录 cookie 则如实报告并落盘）
- 提醒：注册后「我的」等页面靠 `session.revision` 自动刷新（ProfileViewModel 订阅），
  无需手动刷新

驾驶员二轮走查反馈：**退出登录时要显示「退出成功」提示**。修复：`ProfileViewModel.logout()`
清会话后播一次性提示「退出成功」（走本页既有的 Toast 通道）。

**走查结果（2026-10-16）**：注册（含自动登录衔接）、找回密码、标签页、使用手册全部通过；
退出提示已补，驾驶员确认后提交推送（f81e0db）。

## v0.9.2 走查修复·四个问题（2026-10-16，驾驶员二轮走查）

驾驶员原话（两轮反馈合并）：「详情页点赞收藏关注之类的点击时其他的按钮就被禁用了这是怎么回事，
而且我收藏后返回到我的页面，也没有第一时间刷新看到数字的变化，要点击进去才显示」；
「收藏或者取消收藏后回"我的"，数字还是不更新，试了好几次都没用；还有我发现文章的图片都不能
点击放大，长按要有一些常用功能比如保存到本地相册；还有文章收藏评论粉丝页，为什么切换四个时
要整个页面都重新刷新而不是就只一项呢」。

### ① 详情页一个操作在途，全页按钮被禁

- 原因：写操作互斥用的是**全局单键** `busyKey: String?`，界面各处把「busyKey 非空」当成禁用条件
  （作者行的关注/私信、互动栏的点赞/收藏/分享、评分星、付费购买、每条评论的点赞/回复）——
  本意只是给单个操作防双击，实际把整页都禁了。
- 修复：改为**互斥键集合** `busyKeys: Set<String>`（like/fav/follow/rate/cashier/buy/comment/clike-{id}）：
  同一键在途防重复提交，**不同键可并行**（点赞/收藏/关注是互不影响的字段，且站点 nonce 本就可复用）；
  界面按各自的键判断禁用——点收藏时只有收藏自己短暂禁用，点赞/关注/分享/评分照常可点。
  评论点赞细化到 `clike-{评论id}`：只禁这一条评论的操作。

### ② 收藏后数字不更新（真根因：作者页没有任何"返回即刷新"机制）

排查（含实时样本验证）：curl 抓实时用户中心页 + 本机跑真解析器
（`LiveOverviewProbeScratch`）确认服务端与解析都正确（收藏=1 立即反映）。
真正的时序问题在**作者页（文章/收藏/评论/粉丝 四标签页）**：
从「我的」点统计进作者页（如收藏 tab）→ 打开文章 → 收藏/取消收藏 → 返回作者页——
AuthorViewModel 一直存活且**从不刷新**，标签上的「收藏 N」与列表停在旧值；
再从「我的」重新点进（新实例）才显示新值——即驾驶员描述的「要点击进去才显示」。

修复：
- `AuthorViewModel` 订阅 `SakuApp.contentRevision`（详情页写操作成功即自增）→ **静默刷新**：
  不动加载态、不动滚动位置、失败保留现有内容；分页标签只在「仅加载第 1 页」时替换列表
  （深页码只更新头部计数，避免丢已加载内容）；粉丝 tab 只在不处于「关注」子列表时替换
- 「我的」页（ProfileViewModel）另有两层保险：已有的 ON_RESUME 刷新照旧，
  再补 `contentRevision` 订阅（写操作成功即静默重取）+ **下拉刷新**（PullToRefreshBox，
  显式手动入口）+ 刷新失败不再静默：有旧数据时保留页面但弹「刷新失败：xxx」提示

### ③ 正文图片：不能点击放大 / 长按无常用功能

新增 `ui/components/ContentImage.kt`：
- **点图 → 全屏查看**：双指缩放（1–6 倍，平移限位不拖出屏幕）、双击放大/复位、
  未放大时点空白关闭；底部「保存到相册 / 复制链接 / 分享」
- **长按图 → 常用操作**：保存到本地相册 / 复制图片链接 / 分享链接 / 浏览器打开
- 保存 = 抓取图片本身（与网页右键另存同一份图，25MB 上限）经 MediaStore 写入相册
  （Android 10+ 免权限走 Pictures/SakuraXy；9 及以下按需申请存储权限，manifest 已加
  `WRITE_EXTERNAL_STORAGE maxSdkVersion=28`）
- 详情页与使用手册共用（`ContentBlockItem` 增加 onImageTap/onImageLongPress 回调）

（页头还没数据）才整页转圈，首次失败仍整页报错+重试。
