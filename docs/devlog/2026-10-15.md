# 2026-10-15 · 项目立项 → v0.2

一天内从零到驾驶员真机验收两轮。记录关键事实与证据，细节决策见 `总设计案.md`。

## 站点勘察（开工前）

用 curl 实测 sakuraxy.top（WordPress + zibll v9.1），确认三条链路：

| 链路 | 结论 |
|---|---|
| 内容 | `/wp-json/wp/v2/posts|categories`、`?search=` 匿名可读，返回完整正文 |
| 下载 | 正文 `?golink=<base64>&nonce=<hex>` → 再请求得跳转页，`location.href` 即真实网盘地址 |
| 登录 | `/user-sign?tab=signin` → `admin-ajax.php` `action=user_signin`；`captcha_mode=slider` 存在但实测未强制 |

关键发现：**REST 给不到主题数据**。列表卡片的封面兜底、角标、付费徽章、多级分类、作者、
评论/浏览/点赞数、排序、分页只存在于页面 HTML 里 —— 这决定了后面要做"双通道"（REST + HTML 解析）。

## P2 接口层（core，纯 Kotlin JVM）

`WpApi`（REST）、`AuthApi`（登录）、`Golink`（下载链）、`Session`（cookie）+ `SakuClient` 门面。
单测 **42 项全绿**，样本是真实响应的脱敏副本，网络链路用 MockWebServer 本地模拟，全程不外联。

踩坑两则（都有专项测试兜底）：

1. **OkHttp 5 移除了 `encodedQueryParameter`**，且 `queryParameter` 会把 base64 里的 `+` 解码成空格，
   会直接毁掉 golink 链接 → 自实现保留 `+` 的查询参数解析
2. mockwebserver3 的 `RecordedRequest.body` 是 `ByteString`（`.utf8()`），不是 Buffer

## 驾驶员反馈 → 方向修正（重要）

v0.1 被指出**遗漏了大量网站功能**（二级分类、排序、分页、作者、标签、评论、点赞、封面缺失、
正文内链），并明确要求：**目标是与网站功能的完美复刻，不是阉割版**；
UI 重构为底部分页路由导航栏 + 深浅色跟随系统。

这条已写入总设计案（P6 决策 + 功能对照表）与项目记忆，后续按对照表逐项交付。

## P5 数据补全（core 双通道成型）

- `SiteParser`/`SiteApi`：卡片完整信息、排序菜单、分页（含跳页）、分类页头部、文章页统计与面包屑
- `CategoryTree`：按 REST `parent` 还原多级分类树
- `ContentParser` 升级：正文内链保留（站内文章跳 App、外部开浏览器）
- `WpApi.comments`：评论列表（REST 匿名可读）
- 单测 **42 → 62 项全绿**

解析过程中的三个真实坑：

1. 首页卡片**不显示作者名**（只有头像+相对时间）→ 从头像 `alt="XX的头像-SakuraXy"` 兜底提取
2. 付费徽章的数字是锚点内的裸文本节点（`付费资源<span><svg/></span>2`），不在 span 里
3. 卡片封面优先 `data-src`；`thumbnail*.svg` 是占位图必须跳过
